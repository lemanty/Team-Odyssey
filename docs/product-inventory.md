# 商品与库存管理

入口：员工或管理员登录后，**我的账号 → 商品与库存** (`/staff/products`)。

- 搜索中英文名称或编号，筛选全部、已上架、未上架或低库存。
- 新增商品默认未上架；填写双语名称/描述、分类、系列、售价、库存和主图后可以上架。
- PNG/JPEG 图片每张最多 5 MB、2000 万像素；上传保存在 MySQL，另支持现有 `/images/products/` 图片路径。
- 服装必须设置尺码和颜色。已有规格名称固定，停售某规格时将其可售库存设为 0；可以新增规格。
- 有规格时，总可售库存等于各规格库存之和。无规格商品直接修改商品库存。
- 总库存或任一规格库存小于等于阈值时显示补货提醒，编辑页用浅黄色标出低库存规格。
- 取消“上架”并保存即下架；顾客目录、详情和结账均不再允许购买。历史订单保留。
- 保存时检查编辑版本及库存；发生并发编辑、下单或取消补库存后，旧表单不会覆盖最新数据，需重新打开编辑页。
- 已有无规格订单的商品不能直接改为规格库存，以免旧订单取消时无法确定补回的规格。

## 数据库部署

新增 `src/main/resources/db/013-product-management.sql`，创建商品管理信息和图片表，不删除或重置原商品。原商品默认保持上架，中文内容沿用原翻译直到后台保存。

宿主机启动脚本 `Host-Start`（host-all）会执行迁移；已有部署也可执行 `python3 scripts/database.py init`，然后重启应用。迁移与应用代码应一同部署。当前本地开发数据库已执行本次迁移。

## 验证

`./mvnw test` 包括后台角色权限、CSRF、双语搜索、上传、规格总库存、编辑冲突、下架结账拦截及历史订单取消补库存测试。没有接入真实支付或自动推送代码。

### 从旧商品分类升级

在数据库主机上先备份，再用现有的 `python scripts/database.py init` 顺序执行迁移。020 添加子分类列，021 按原商品 ID 回填分类。完成后再运行新版网站或导入示例商品。已执行过 020 的数据库也需要执行 021。

021 会列出仍需核对的旧服装 ID。对于无法确定男女分类的商品，可以先从首页“探索服装”找到，再由管理员确认分类。若报告中出现 `possible_duplicate_id`，请核对两条商品的库存、规格及历史订单，再决定如何处理。迁移保留两个 ID。
