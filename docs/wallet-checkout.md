# 储值余额结账

入口：购物车 → 结账 → 支付方式。默认选中储值余额支付，也可明确选择线下付款（只提交订单，不扣款、不标记已支付）。

## 顾客操作

1. 管理员在储值管理中确认入账；本模块不提供真实银行卡充值或提现。
2. 结账页显示可用余额与会员优惠后的实付金额。余额不足时显示差额；服务端也会重新核对余额，失败后保留购物车和配送填写内容。
3. 成功支付后，在订单详情查看支付状态，在“我的储值”查看带订单链接的支付流水。
4. 仅待备货订单可由订单所属顾客取消。取消余额支付订单时，将**当时实际扣款金额**退回同一账户，不按当前商品价格或会员等级重算。

支付状态与配送状态分开存储。线下订单显示“未记录收款”，取消不会产生退款；旧订单显示“支付状态未记录”，不会伪造历史收款或补扣余额。零金额订单不生成零金额的余额流水。

## 一致性

- 下单、会员优惠快照、余额扣款、库存扣减和清空购物车属于同一数据库事务；任一步失败整体回滚。
- 账户行锁与管理员调账使用相同的序列化依据，并发订单不能将余额扣成负数。
- 同一结账令牌重复请求返回原订单；取消通过订单状态条件更新保证最多退款一次。
- 退款、取消状态、库存恢复同一事务提交。若退款会超过现有储值上限（€9,999,999,999.99），取消整体失败并提示管理员处理余额，不会出现取消成功但未退款的状态。
- 流水区分管理员调账、订单支付、订单退款，保留变动后余额及关联订单。

## 部署

执行 `src/main/resources/db/014-wallet-checkout.sql`，需先有订单表与 `011-wallet.sql`。主机执行 `python3 scripts/database.py init` 或通过 Host-Start 启动即可应用迁移，再重启网站。迁移只新增支付快照表，不改变已有订单与余额。本机开发数据库已应用此迁移。

## 测试

`./mvnw test`（Windows：`.\mvnw.cmd test`）。`WalletCheckoutTests` 覆盖重复扣款/退款、余额不足保留购物车、扣款后异常回滚、优惠后金额、并发消费与退款、越权取消、备货后禁止取消、线下/历史/零金额订单以及 HTTP 页面和 CSRF 校验。测试使用隔离的 H2 数据库，不操作共享账户储值。
